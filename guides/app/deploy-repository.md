## 介绍

`构建仓库` 用于管理常规发布的构建版本，实现构建与发布的分离：一次构建产生的产物可以被多个发布申请复用，例如先发布到测试环境验证，再用同一个产物发布到生产环境，避免重复构建带来的差异。

![构建仓库](/img/docs/4.0/zh/repository.jpg)

列表按应用聚合展示最新版本、构建时间、构建人与状态，展开后可以看到该应用的全部构建版本。

## 新建构建

点击 **新建** 选择应用与发布环境（对应一个常规发布的发布配置），然后填写：

![新建构建](/img/docs/4.0/zh/repository-form.jpg)

- **构建版本**：自定义的版本号，例如 `v1.2.0`，建议保持唯一以便区分（系统不会强制校验）。
- **选择分支 / 标签 / 版本**：选择 `Branch` 并指定 `Commit ID`，或者选择 `Tag`，决定构建哪份代码。
- **备注信息**：可选。

提交后立即开始构建，构建过程即发布配置中的 **构建阶段**（代码检出前 / 后执行钩子与打包），点击 **日志** 可以实时查看构建输出。

## 操作说明

- **构建**：对已完成的版本再次构建会覆盖已有的产物，可用于构建失败后的重试。
- **日志**：查看构建过程的完整输出。
- **删除**：点击版本号打开详情，在详情底部可以删除该版本及其产物；已被发布申请引用的版本无法删除，会在对应发布申请删除时自动清理。

## 与发布申请的关系

- 在 [新建发布申请](/docs/deploy-request) 时选择 `构建仓库` 中的版本，发布会直接使用已有产物，跳过构建阶段。
- 新建发布申请时选择分支或 Tag，`Spug` 会自动创建对应的构建版本并在发布时完成构建。
- 每日清理任务会保留每个发布配置最近 `版本数量 + 1` 次发布申请所引用的构建产物，更早的会被自动删除；未被任何发布申请引用的构建记录不受此清理影响。

## 权限说明

构建仓库的权限位于 `角色管理 / 功能权限 / 应用发布 / 构建仓库`，包含查看构建、新建版本、执行构建和删除版本四项；同时受角色的 [发布权限](/docs/system-role#deploy-perm)（可发布的环境与应用）限制。
