## 介绍

用于维护应用在各环境下的配置项，配置以键值对形式按环境存放；其他应用通过 **依赖** 该应用即可获取到它的全部配置。

![应用配置](/img/docs/4.0/zh/config.jpg)

- 比较典型的例子：应用 B 需要调用应用 A 的某接口，那么应用 B 必然需要知道应用 A 的 IP 或域名，这时可以把地址维护在应用 A 的配置中，再让应用 B **依赖** 应用 A 来获取。为什么不把这个配置放在应用 B 里呢？因为如果还有应用 C / D / E / F 也要调用 A，在每个应用中都配置一遍既麻烦又难以维护。

## 配置项

- **应用名称 / 标识符 / 备注信息**：与 [应用发布 / 应用管理](/docs/deploy-app) 中的应用是同一份数据，标识符会作为生成配置的前缀。

## 依赖

点击应用行的 **依赖** 可以设置该应用依赖的其他应用与服务，设置后该应用（通过 API 或发布时的环境变量）能够获取到所依赖应用以及所依赖服务的全部配置。

![配置依赖](/img/docs/4.0/zh/config-app-rel.jpg)

## 小提示

- 4.0 中应用配置不再区分 `公共` / `私有` 类型，被依赖时该应用的全部配置都会提供给依赖方，请不要把不希望共享的敏感配置放在会被其他应用依赖的应用中。
- 配置中心用于解决不同环境间配置的差异，如果各个环境下某配置的值都是相同的，就可以直接在代码中硬编码而不需要把这些配置放到配置中心维护。
- 点击 **配置** 进入该应用的配置管理页面，用法见 [配置管理](/docs/conf-set)。
